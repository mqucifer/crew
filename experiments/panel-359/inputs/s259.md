As a **Developer**, I want **a Dockerfile at the repository root that builds a minimal linux image with the sprint-metrics CLI installed and the sprint-metrics executable on the default PATH**, so that **the release workflow can build and push multi-arch images to ghcr.io and CI can verify the image builds on every pull request**.

## Acceptance criteria

1. **Given** the repository in its current state with pyproject.toml defining the sprint-metrics console script and src/sprint_metrics/ containing the package
   **When** docker build -t sprint-metrics-test . is executed from the repository root
   **Then** the build exits 0 and docker run sprint-metrics-test sprint-metrics --help exits 0 with stdout containing the string sprint-metrics

2. **Given** the image built by the previous criterion and a cards.json file on the host containing the JSON array [{"created": "2024-01-03", "started": "2024-01-05", "completed": "2024-01-10"}]
   **When** docker run --rm -v <host-path>/cards.json:/input/cards.json sprint-metrics-test sprint-metrics /input/cards.json is executed
   **Then** the command exits 0 and stdout contains the line | Current | 5 days | 7 days | 1 | 0 | 0 days | 0% | 100% | — |

3. **Given** the Dockerfile in the repository
   **When** the file content is read and searched for the substrings amd64, arm64, x86_64, and aarch64
   **Then** none of those four substrings appear in any line of the Dockerfile, confirming the build is not pinned to a specific CPU architecture

**Estimate** — 2 points
