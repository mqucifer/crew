A new crew-wide rule applies: constitution §19.8 (crew#352), what ships as an image is proven the way it's run. This project publishes a container image (release_how), so its design must say how CI proves, on every pull request, each part of §19.8: the image starts as its docs say to run it, without repeating the program's name; a service mode is reached the way a user reaches it, started detached with its port published and answering from outside the container; it runs as a user other than root; and its base is pinned by digest and kept current by a dependency updater. Which tools do it is your choice. Research on sprint-metrics#269's Dockerfile (crew#335): hadolint passes a Dockerfile with no USER instruction; trivy's config scan flags it (AVD-DS-0002). Docker stays CI-only, never in the local checks.
